# Back_B 구현 및 연결 현황 (2026-11-17)

기존 로컬 stf 저장소의 Back_B 브랜치에서 B 담당 40개 API의 Controller·DTO·응용 서비스, 이벤트·스케줄러와 JDBC 어댑터를 구현했다.

| 영역 | 구현 |
|---|---|
| OVW-001~002, INV-001~003 | 배치·현재 재고·추이·상세·조립 정지/복구/손실 예측 조회, 생산 이벤트와 주기 계산 |
| ALM-001~008, MEAS-002 | 현재·최근 종료·상세·효과 조회, 담당 지정·조치·오경보, 과거 조치 추천과 전후 10분 비교 |
| HST-001~002, PRT-001~004 | 이력·검색·페이징·수명 조회, 교체 등록·기준 시각 갱신, 알람 조치와 원자적 교체 저장 |
| STA-001~008 | 대응·오경보·일별 건수·가동률·정지시간·순위·실제 손실·손실 방지 조회 |
| TLG-001~006 | 연결 URL·상태·해제·시험 전송·전송 이력, private /start long polling, 1회용 토큰·재시도 |
| DUT-001~006 | 당번 CRUD·현재·캘린더, 공백·중복·보전 담당자 검증, 마지막 예정 일정 삭제 제한 |
| 이벤트·스케줄러 | 재알림·당번 전환·재고 갱신, 생산·복귀·재발·효과 확인·자동 종료, 커밋 후 발행·DB 보관·재시도 |
| 실시간·보안 | 7개 STOMP 토픽, Bearer JWT와 폐기 확인, 개인 큐 제한, 내부 수집 API 키 |
| DB 연결 | 원본 V1/V2와 신규 V3, JDBC 저장·조회·잠금·낙관적 충돌 검사·조치/교체 롤백 |

INT-001 연결 어댑터도 선택적으로 제공한다. A의 수집 Controller를 쓸 때는 stf.backend-b.ingestion-enabled를 꺼 중복 등록을 피한다.

## 검증

- Gradle clean test --no-daemon: 233개 통과, 실패·오류·건너뜀 0.
- MockMvc: B 담당 40개 경로 정상·비로그인·권한·입력 오류.
- H2: 저장·조회·롤백·스케줄러 멱등성과 수집부터 자동 종료까지의 흐름.
- MySQL 8.4: 별도 임시 컨테이너에서 V1/V2/V3·시드·읽기 포트·긴 조치/교체 저장·당번 중복 거부. 기존 개발 DB에는 적용하지 않았다.
- OpenAPI lint 통과. STOMP 전용 7개 unused 오탐만 위치별 제외하며 실제 이벤트 필드는 별도 테스트한다.

## 남은 실제 환경 연결

| 항목 | 필요한 작업 |
|---|---|
| 공유 MySQL | DB 담당자가 V3와 추가 테이블을 검토 후 적용. 공유 서버에는 실행하지 않음 |
| A 인증·사용자 | A의 로그인/회원가입 API·SessionStore와 연결. 같은 JWT issuer/secret 및 폐기 저장소 계약 사용 |
| 프론트 | Back_B를 검토·병합한 뒤 frontend에서 npm run api:sync와 npm run check. 현재 스크립트는 origin/backend 고정 |
| 텔레그램 | 실제 봇 이름·토큰 환경변수 설정 후 private 실발송 확인. 이번에는 외부 메시지를 보내지 않음 |
| 현장 데이터 | Node-RED 대상 URL·내부 키, PLC 주소/배율·임계값·생산 카운터·운영 단가 설정 및 시연 |

위 항목은 배포·계약·외부 연결 확인 사항이다. 실행과 팀 연결 방법은 BACKEND_B_INTEGRATION.md에 있다.
